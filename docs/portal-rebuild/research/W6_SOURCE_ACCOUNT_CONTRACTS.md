## Proposed API and bounded design

One fixed proposed RPC `concierge_source_account_command_v1(p_command)` with exactly three actions:

| Action | Input after schemaVersion/action | Result |
| --- | --- | --- |
| list_source_consents_v1 | snapshot nullable, cursor nullable numeric offset, limit | Own safe records with exact disclosure text/ref and manual attribution, paged against one snapshot; or explicit unavailable |
| withdraw_source_consent_v1 | requestId, expectedRevision, exact consent id/purpose/disclosure ref | Linked client_portal event and original hash/UUID/expected+1 receipt |
| request_status_v1 | original requestId | Original own committed receipt, actually queried absence, or explicit unavailable/purged |

No command carries client/actor/current/permission/approved, arbitrary URL/RPC, source/raw/name/path/reference/handle/grant fields, re-consent, upload/read/delete/export or a new right. Purposes remain exactly service_storage and service_review. Training/transcription/model transmission/raw export remain disabled. A later finite task-context protocol remains a complete-goal obligation.

The smallest attribution is the actual server recorder UUID and recording instant, without a guessed staff name/role label or private confirmation reference. Manual occurrence is independently known or unknown. If actual lineage, exact disclosure, recorder or lifecycle cannot be produced, return unavailable, never adopt a draft/source/client by inference or fabricate empty history. An effective not_withdrawn record is display data, not operation authority. Later portal events are separate from manual decisions.

New engineering proposals: request 100000 UTF8 bytes; result 1800000 and page 400000 following inspected Review practical budgets; at most 100 rows per page and 4000 Unicode scalars per disclosure, with the aggregate page budget also enforced. These do not change other caps or establish existing Account limits. Numeric offset cursors bind to a stable snapshot; total has no first100 history ceiling. Only complete validated page composition can return a complete collection. The actual producer must query completely before asserting an available empty page.

Disclosure text is exact plain data, never executable markup, with BOM/CRLF/decomposition retained. Version/hash/text consistency is checked across the complete collection. Digests are declared producer references, not cryptographic verification here; no previous hash algorithm is inferred. Before admission the Source policy/disclosure producer must pin a common exact-byte/purpose/version hashing rule and immutable record linkage. No async helper is needed for this parser/mapper, so no await/current-lease success model is invented. Request hashes are supplied from the independent original command journal, never derived from a receipt.
